# Component catalog

## Purpose

- Own the local catalog of the extracted UI variants and their memory-only examples.

## Ownership

- App.svelte provides component pages at /rachana/Name and /komandir/Name, and shared family pages at /compare/family.
- Preview.svelte loads one variant at /preview/variant/Name. RachanaDemos and KomandirDemos render the actual package components.
- catalog.json is a runtime catalog generated by ../scripts/update-catalog.ts from package sources and demo markup. Refresh it when components or examples change.

## Local Contracts

- Keep examples independent of application source, settings, files, devices and update services. Use memory data and callbacks.
- Keep both variants visible in a family. Do not normalize their behavior to make a comparison match.
- Pair controls by name or the explicit Checkbox/CheckButton, Select/Dropdown, ModalDialog/WindowDialog and Help/HelpButton aliases. Keep unpaired controls visible on their own row.
- Use one document per preview iframe. The preserved global selectors and overlay stacks must not leak between variants or into the documentation shell.
- Each public component needs its own page and a real rendered example. Do not replace a component with a screenshot or copied control markup.
- Keep result/status space reserved. Longer source and integration details belong in disclosure sections.
- Host defaults use bundled icons and English labels. Window examples omit persistence keys; native and application capabilities require explicit host callbacks.

## Verification

- bun run check:demo from the repository root checks the packages and demo. bun run demo starts loopback port 3212 without opening a browser.
- All 65 preview routes were mounted in the hidden browser. Representative number, color, menu and window actions were checked. This is not device or full application acceptance.
